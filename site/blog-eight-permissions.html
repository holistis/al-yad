v0.1.15: exactly eight permissions, enforced automatically

We re-audited exactly what the Chrome Web Store version of Yad is allowed to do in your browser, brought it down to eight concrete permissions, and built an automated check so it can never silently grow beyond that list again.

Every browser extension asks for permissions, and most people never read the list. We did, on our own extension, with fresh eyes, and wrote down exactly what the store version needs: nativeMessaging (to talk to the companion app on your machine), sidePanel, storage, tabs, scripting, webNavigation, downloads, and tabGroups (that is the tab-group feature from the last update). That is the full list. No cookie access, no debugger access, nothing beyond it.

The part that matters long-term is not the list itself, it is that a human checking a list by hand, once, does not stay true forever. So we built a gate: a script that opens the exact file about to be uploaded to the Chrome Web Store, reads the real manifest inside it, and refuses the upload outright if anything outside that fixed list shows up. No override switch. It is wired into the same pipeline that talks to the Chrome Web Store API, so there is no manual step where it could be skipped.

Version 0.1.15 just went through that gate and has been submitted to Google for review. Your current installed version keeps working exactly as it does now until that review finishes. No gap.

This is what "runs on your own machine" and "locked, capped, and stoppable" are supposed to mean in practice. Not just on launch day, checked again, automatically, every time something new goes out.
